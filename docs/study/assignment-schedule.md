# Assignment schedule

Counterbalanced within-participant design (protocol §5). Scenario order is fixed (Task 1 = **A**, Task 2 = **B**); the **condition order alternates**:

- **AB**: Task 1 Baseline · Scenario A → Task 2 MacroTable · Scenario B
- **BA**: Task 1 MacroTable · Scenario A → Task 2 Baseline · Scenario B

Pilot participants use `T001–T006` so pilot data can never be mixed with main-study data (`P001–P040`). Assign codes strictly in order; if a participant drops out, **do not reuse the code** — note it and continue with the next one. The full list with all links is in [`assignment-schedule.csv`](assignment-schedule.csv).

> If the team changes scenarios or the design at freeze, regenerate this file — don't hand-edit links.
